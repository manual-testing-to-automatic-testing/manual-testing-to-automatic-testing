# Specification: manual-testing-to-automatic-testing.github.io

## Summary

Publish the manual testing to automatic testing training programme as a static website at <https://manual-testing-to-automatic-testing.github.io>, so that participants, managers, mentors, and organisers can read every document, find their track, and complete the capability self-assessment, without cloning anything.

This file covers only the website. The programme itself is specified in the monorepo's [`spec/index.md`](../../spec/index.md). Publishing is in the monorepo's [`spec/monorepo-github-pages/`](../../spec/monorepo-github-pages/index.md).

## Scope

In scope: rendering the monorepo's Markdown documents, the self-assessment tool, search, the sitemap, and the site chrome.

Out of scope: the practice repository's code (linked on GitHub, not rendered), any server, account, or storage of personal data.

## Principles and rules

1. **Static.** Every page is prerendered to HTML at build time. There is no server, no database, and no runtime API. GitHub Pages serves `build/` as files.
2. **Self-contained.** The project builds from its own directory and reads nothing outside it at build time, so it still builds after being pushed to its own repository. Its inputs are vendored by `bin/sync`.
3. **The monorepo is the source of truth.** Documents are edited there, never here.
4. **Same scoring as the monorepo.** The self-assessment scores exactly as `scripts/capability_index.py` does.
5. **Private by design.** Self-assessment answers stay in the reader's browser. Nothing is sent anywhere.
6. **Generic.** The theme picker offers only Lily's generic themes, not national government or public-sector themes, because the programme is written for a generic organisation.
7. **Single column, full width, no sidebars.** Every page is one column, the full width of the browser: no left or right sidebars, no sticky side panels, no breadcrumbs, and no contents lists.
8. **Accessible.** Semantic HTML, one `h1` per page, visible focus, a skip link, labelled form controls, focusable scroll regions, and WCAG 2.2 AA contrast in the default theme. No colour-only signalling: every status is also written as text.

## Detail

### Vendored inputs

Refreshed by `bin/sync`. Never edit them by hand.

| Path | Source in the monorepo |
| --- | --- |
| `content/docs/` | `README.md`, `plan.md`, `tasks.md`, and every Markdown file in `spec/`, `materials/`, and `instruments/`, plus the practice repository's README, CONTRIBUTING, spec, test READMEs, and FHIR sandbox README |
| `content/instruments/` | `instruments/*.tsv`, generated by `scripts/build_instrument.py` |
| `static/downloads/` | every TSV in `instruments/` and `materials/`, at the same path |
| `static/assets/themes/` | Lily's generic reference themes, per `bin/lily-themes.txt` |

### URLs

Trailing slashes always. Every page is under a locale (see `spec/locales/index.md`).

| Path | Page |
| --- | --- |
| `/` | Redirects to `/en-001/` |
| `/<locale>/` | Home: the programme's summary, and two buttons: **Find your track** (the tracks page, `/<locale>/tracks/`, which lists every track and links to its page) and **Read the programme**; then a **Contents** list of links to the main pages, such as the tracks, curriculum, mentor, line manager, modules, and gates. No tiles: the navigation and the link picker reach every main page |
| `/<locale>/<slug>/` | A document, at a flat URL in full words: its file or folder name, with no parent folders. `spec/index.md` is `spec`, `materials/gates/calibration-guide.md` is `calibration-guide`, `materials/modules/module-10-browser-automation-fundamentals/index.md` is `module-10-browser-automation-fundamentals`, the root `README.md` is `about`. A few names are written out, such as `human-resources-briefing`, and two documents may never share a URL (the build fails) |
| `/<locale>/track-for-<band and role level>/` | A track's page, named by its guide's title, for example `track-for-band-3-associate-quality-assurance-test-analyst`: the track guide from `materials/tracks/<track>/index.md`, then the track's capability self-assessment, at `#self-assessment` |
| `/<locale>/curriculum/<module name>/` | A module's training content, from `materials/modules/module-<n>-<module name>/training.md`, for example `curriculum/basics-of-an-ai-assistant` |
| `/<locale>/istqb/certified-tester-advanced-level/test-automation-engineering/syllabus/<section>/` | The CTAL-TAE syllabus explained, one page per chapter, section, and learning objective, from `materials/modules/module-5-istqb-certified-tester-advanced-level-test-automation-engineer/syllabus/`, for example `7-1-3-identify-where-test-automation-produces-unexpected-results`; the folder's `index.md` is the contents page |
| `/<locale>/search/?<query>` | Search results, from the search picker |
| `/<locale>/search-index.json` | The search index |
| `/downloads/<path>.tsv` | A vendored TSV |
| `/sitemap.xml` | Every page |

### Documents

Each document is rendered from its Markdown at build time:

- Headings get GitHub's anchor ids, so links such as `spec/#decisions` work as they do on GitHub.
- A relative link to another document becomes that document's page. A link to a vendored TSV becomes its download. Any other relative link, such as practice repository code, goes to that path in the monorepo on GitHub. A link outside the monorepo goes to the monorepo's home on GitHub.
- Wide tables and code blocks scroll inside focusable regions.
- Every document page ends with a link to its source on GitHub.

### Self-assessment

`src/lib/components/SelfAssessment.svelte`, with scoring in `src/lib/capability.ts`, on each track's page, after the track guide. For that track, it shows every item in Parts A, B, and C of the instrument, each in a `fieldset` whose legend names the item, with:

- three ratings, Self, Manager, and Agreed, each a labelled select using the item's scale (Not yet, Partly, Meets; a factor level; or 0 to 4)
- the expected level and its description, and for skills the next level
- for Band 3 job evaluation factors, an "Expected (Gate 0)" select, because those levels are agreed at Gate 0
- evidence and development action text areas
- the agreed status, as text.

The summary shows the capability index for Parts A, B, and C and overall, for each of Self, Manager, and Agreed (only Agreed counts). It checks the chosen gate's threshold, lists skills more than one level below expected at Gates 4 and 5, states the gate's other conditions to check by hand, and lists items where Self and Manager differ by more than one level, to discuss first.

Answers are saved to `localStorage` under `manual-testing-to-automatic-testing:self-assessment:<track>` and restored on the next visit. **Export TSV** downloads `<file name>--gate-<n>.tsv`, such as `band-5-quality-assurance-test-analyst--gate-1.tsv`, in the instrument's columns, with `self_rating`, `manager_rating`, `agreed_rating`, `status`, `evidence`, and `ilp_action` filled in, which `scripts/capability_index.py` scores. **Import TSV** reads such a file back, and refuses a file for another track. **Clear** asks first. Nothing is sent anywhere.

### Site tools

Every page carries `PickerBar` (`@lilydesignsystem/svelte-picker-bar`) in the header: a link picker (a home icon offering every main page, so navigation is one tap away on any screen), search, theme, language, text size, and share. The header is a grid: the brand and the PickerBar share the first row, with the PickerBar on the right, and the navigation links have the second row, so the PickerBar never wraps under the brand. On screens narrower than 40rem, the PickerBar takes its own row under the brand. The theme defaults to `corporate` and is stored under `manual-testing-to-automatic-testing:theme`. The text size is stored under `manual-testing-to-automatic-testing:text-size`.

## Acceptance criteria

- `pnpm check` reports no errors and no warnings.
- `pnpm build` succeeds with strict prerendering, so no internal link is broken.
- `pnpm test` passes: every page in the sitemap returns 200 with one `h1`, a title, and `lang`; the self-assessment scores, persists, exports, and imports correctly; and axe finds no WCAG 2.2 AA violations on the tested pages, including a rated self-assessment.
- An exported TSV gives the same capability index in the browser and in `scripts/capability_index.py`.
- `./bin/sync --check` passes before every publish.
